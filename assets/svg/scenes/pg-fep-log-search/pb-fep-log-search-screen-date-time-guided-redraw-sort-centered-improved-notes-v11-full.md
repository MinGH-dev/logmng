# PB FEP Log 화면 시안 코멘트 v11 (전체본)

## 1. 기준 파일
- 대상 시안: `pb-fep-log-search-screen-date-time-guided-redraw-sort-centered-improved-v10.svg`
- 본 문서는 최신 SVG 시안을 기준으로 한 **전체 코멘트 문서**이다.
- 이전 버전에서 누적 반영된 내용을 포함하며, 변경 이력만이 아니라 현재 상태의 전체 기준을 정리한다.

## 2. 화면 목적
- 운영자가 PB FEP 로그를 빠르게 조회하고 탐색할 수 있어야 한다.
- 기본 조회 단위는 하루이며, 필요 시 시간 범위를 세밀하게 좁혀 재검색할 수 있어야 한다.
- 한 화면에서 가능한 많은 로그를 확인할 수 있도록 검색 패널은 compact하게 유지하고, 그리드 영역은 넓게 확보한다.
- `data` 전문은 기본 접힘 상태로 두고 필요한 행만 개별적으로 펼쳐 볼 수 있어야 한다.

## 3. 상단 검색 패널
### 3.1 검색 조건 구성
- 검색 조건은 다음 순서로 배치한다.
  - 시작일시
  - 종료일시
  - Login ID
  - TR Code
  - 키워드 검색
  - 검색 버튼
  - 초기화 버튼
- 검색 패널은 1줄 배치를 우선으로 하며, 현재 SVG는 compact한 운영형 레이아웃을 기준으로 한다.
- 입력창 높이는 축소하여 상단 검색 패널의 세로 높이를 최소화한다.
- 검색/초기화 버튼도 compact 높이에 맞춘다.
- 검색 조건 영역과 우측 버튼 영역은 너무 붙어 보이지 않도록 일정 간격을 둔다.

### 3.2 검색 조건 규칙
- 필수 입력값
  - 조회 일시 범위(시작일시, 종료일시)
  - Login ID
- 선택 입력값
  - TR Code
  - 키워드 검색
- 제외 항목
  - 매체코드
- 검증 규칙
  - 시작일시는 종료일시보다 늦을 수 없다.
  - Login ID는 공백 입력 불가이다.
  - 키워드는 쉼표 구분 다중 입력을 허용한다.

### 3.3 복호화 관련 제어
- 기존 체크박스는 제거한다.
- `복호화 승인 요청`은 **버튼**으로 표현한다.
- 이 버튼은 그리드 상단 제어행의 왼쪽 그룹에 배치한다.
- 즉, 검색 패널 안이 아니라 그리드 진입 전 제어영역에서 `전체 펼치기`와 나란히 위치한다.

## 4. 그리드 상단 제어영역
- 그리드 헤더 안이 아니라 **그리드 바깥 상단 영역**에 별도 제어행을 둔다.
- 이 제어행에는 다음 요소가 포함된다.
  - `복호화 승인 요청` 버튼
  - `전체 펼치기` 버튼
- `전체 펼치기`는 그리드 헤더와 겹치지 않도록 헤더 외부에 독립 배치한다.
- 그리드 헤더 내부에는 컬럼명만 표시하고, 별도 제어 기능은 넣지 않는다.

## 5. 결과 그리드 스타일
### 5.1 공통 스타일
- dense table 스타일을 사용한다.
- 세로 구분선은 제거한다.
- 행 hover 시 배경색이 약하게 달라지는 효과를 준다.
- 헤더와 셀의 텍스트는 상하좌우 가운데 정렬한다.
- 본문 텍스트는 검은색 기준으로 맞춘다.
- 그리드 라인은 과하지 않은 연회색으로 유지한다.

### 5.2 표시 건수 및 페이지네이션
- 기본 page size는 25건이다.
- 선택 가능한 page size는 25 / 50 / 100 이다.
- 페이지 번호는 하단 중앙 정렬이다.
- page size 드롭다운은 하단 우측이다.
- 설명성 코멘트 텍스트는 화면에서 제거하고, 기능 요소만 남긴다.
- 페이지네이션 바는 항상 보이는 구조를 유지한다.

### 5.3 스크롤 정책
- **전체 화면에는 스크롤이 없어야 한다.**
- 스크롤은 **그리드 내부 본문 영역에만** 존재해야 한다.
- 헤더 및 하단 페이지네이션 영역은 고정된 상태로 유지하고, 목록 데이터 영역만 스크롤되도록 해석한다.

## 6. data 컬럼 / 전문보기 정책
### 6.1 행별 액션 표현
- 행별 전문보기는 토글 스위치 형태가 아니라 **텍스트 액션 형태**로 표현한다.
- 접힘 상태: `전문보기 ▾`
- 펼침 상태: `접기 ▴`
- 즉, 사용자는 버튼/링크형 액션을 눌러 확장 상태를 바꾸는 것으로 인식해야 한다.
- 이전 토글형 pill 또는 switch 잔재는 두지 않는다.

### 6.2 전문 데이터 표현
- 확장 영역의 전문 데이터는 JSON 블록이 아니라 **stream data 느낌**으로 표현한다.
- 긴 전문을 가정하여 monospace 계열 또는 로그 친화적 표현이 적합하다.
- 확장 영역은 각 행 바로 아래에 펼쳐지는 구조로 그린다.
- 현재 SVG에는 전문보기 시 펼쳐진 영역이 포함되어 있어야 한다.

### 6.3 다중 확장 규칙
- 각 행은 독립적으로 expand/collapse 가능하다.
- 다른 행을 열어도 기존 펼침 상태는 유지되어야 한다.
- 단일 아코디언이 아니라 **다중 확장 가능한 구조**여야 한다.
- 상태 모델은 `expandedRowKeys` 기준이 적합하다.

## 7. 전체 펼치기 동작 규칙
- `전체 펼치기`는 data 컬럼의 모든 행을 펼치는 기능이다.
- 이 제어는 그리드 헤더 안이 아니라 그리드 상단 별도 제어행에 존재한다.
- 전체 펼치기가 적용된 상태에서 사용자가 행 하나라도 수동으로 닫으면, **전체 펼치기 활성 상태는 해제**된다.
- 이 경우 전체 펼치기 버튼은 “현재 전체 확장 상태가 아님”을 나타내는 비활성/해제 상태로 돌아간다.
- 이후 사용자는 다시 `전체 펼치기`를 눌러 전체 확장을 적용할 수 있어야 한다.
- 이 규칙은 구현 코멘트로 반드시 유지한다.

## 8. 검색/페이지 전환/상태 유지 규칙
- 한번 검색한 뒤에는 해당 검색 조건이 유지되어야 한다.
- 페이지를 전환해도 검색 조건은 유지되어야 한다.
- 페이지를 전환해도 펼치기 상태는 유지되어야 한다.
- 검색 버튼 클릭 시 page는 1로 초기화한다.
- page size 변경 시 page는 1로 초기화한다.
- 정렬 변경 시 검색 조건은 유지한다.

## 9. 정렬 규칙
- 초기 정렬은 `log_timestamp desc` 이다.
- 각 컬럼 헤더는 정렬 가능해야 한다.
- 정렬 클릭 순서는 다음과 같다.
  - `no sort → desc → asc → no sort`
- `no sort` 상태가 되면 해당 컬럼은 정렬 조건 목록에서 제거한다.
- 새로운 컬럼 정렬 시 기존 정렬 상태를 유지한 채 새 정렬을 추가/변경한다.
- 즉, 항상 초기 raw 결과 기준으로 덮어쓰지 않고, **현재 적용된 정렬 상태를 누적 유지**한다.
- 정렬되지 않은 컬럼은 양방향 정렬 가능 아이콘으로 표현 가능하다.

## 10. 접근성 및 운영성 메모
- 펼치기/접기 액션에는 aria-label을 부여하는 것이 좋다.
- 날짜 입력은 키보드 입력과 선택 UI를 함께 지원하면 좋다.
- 검색 결과가 없을 때 empty state 문구가 필요하다.
- 로딩 중에는 skeleton 또는 progress 표시를 권장한다.

## 11. SVG 반영 상태 요약
현재 최신 SVG 기준으로 다음이 반영되어 있다.
- 상단 안내 코멘트 제거
- 검색 패널 compact화
- 그리드 상단 별도 제어행 배치
- `복호화 승인 요청` 버튼 적용
- `전체 펼치기` 버튼을 헤더 바깥으로 이동
- 세로 구분선 제거
- hover 효과 반영
- 셀 텍스트 중앙 정렬 반영
- 행별 `전문보기 ▾ / 접기 ▴` 표현 반영
- stream data 확장 영역 반영
- 화면 전체 스크롤 제거
- 그리드 내부 본문 스크롤 구조 반영
- 하단 중앙 페이지네이션 / 우측 page size 드롭다운 유지

## 12. 구현 시 주의사항
- row key가 안정적이지 않으면 확장 상태 유지가 깨질 수 있다.
- page 전환 시 expandedRowKeys 유지 범위를 명확히 정의해야 한다.
- 전체 펼치기와 개별 접기의 상태 동기화 규칙을 UI와 상태 로직에서 일관되게 처리해야 한다.
- 확장 영역이 많은 경우 렌더링 성능을 확인해야 한다.
- `복호화 승인 요청`은 실제 권한/보안 정책과 연계 여부를 별도 확인해야 한다.

## 13. 최종 해석
이 시안은 운영형 로그 조회 화면으로서,
- 상단은 compact한 검색 영역,
- 중간은 넓은 dense grid,
- 하단은 고정 페이지네이션,
- 스크롤은 오직 그리드 내부,
- 전문은 필요 시 행별 확장,
- 전체 펼치기와 복호화 관련 제어는 그리드 상단 제어행
이라는 구조를 기준으로 구현하면 된다.
