# 20260225 - 사이드바 검색 메뉴 표시 및 스크롤 복구

## 1. 사용자 요건 내용

### 요건 설명

사이드바(react-pro-sidebar 기반)에서 다음 두 가지 문제가 있다.

- **문제 1 — 검색 메뉴 계층 표시**: "검색하기"와 "검색 이력"이 여전히 서브메뉴처럼만 들여쓰기되어 보이고, "로그 검색"이 "이력·승인", "통계", "관리"와 **동일한 최상위 레벨**로 명확히 보이지 않는다. 그 결과 "검색하기"/"검색 이력"이 부모 없이 들여쓰기된 항목처럼 보인다. "로그 검색"을 최상위 부모로 명확히 보이게 하고, "검색하기"/"검색 이력"을 그 자식으로 계층이 올바르게 표시되어야 한다.

- **문제 2 — 스크롤 회복(회귀 수정)**: 사용자가 "이력·승인" 하위로 진입할 때(예: "활동 이력" 선택), "검색하기"와 "검색 이력" 메뉴가 위로 밀려나며 **사이드바에서 보이지 않게 된다**. react-pro-sidebar 최초 적용 시에는 해당 현상이 없었고, 이후 회귀한 것으로 보인다. "이력·승인"을 펼치고 하위 항목을 선택한 상태에서도 **사이드바 메뉴 영역에 세로 스크롤**이 동작하여, 스크롤을 올리면 "로그 검색" 및 "검색하기"/"검색 이력"에 접근할 수 있도록 복구해야 한다.

### 사용자 시나리오

1. 로그인 후 앱 메인 화면 진입, 왼쪽 사이드바 확인.
2. **문제 1**: "검색하기", "검색 이력"이 "이력·승인", "통계", "관리"와 같은 최상위와 구분 없이 들여쓰기만 되어 있고, "로그 검색"이 동일 레벨의 부모로 보이지 않음.
3. "이력·승인" 클릭 후 "활동 이력" 등 하위 항목 선택.
4. **문제 2**: "검색하기", "검색 이력"(및 "로그 검색")이 화면 위로 밀려나 더 이상 보이지 않으며, 스크롤로 올려서 볼 수 없음.

### 기대 결과

- **문제 1**: "로그 검색"이 "이력·승인", "통계", "관리"와 **동일한 최상위 레벨**로 한 줄에 명확히 보이고, "검색하기"와 "검색 이력"은 그 **자식**으로 들여쓰기·시각적 종속이 명확히 표시된다(고아처럼 들여쓰기만 된 항목이 아님).
- **문제 2**: "이력·승인"이 펼쳐지고 하위 항목이 선택된 상태에서도, **사이드바 메뉴 영역이 세로 스크롤 가능**하며, 스크롤을 올리면 "로그 검색" 및 "검색하기"/"검색 이력"에 접근 가능하다(라이브러리 최초 적용 시 동작하던 것과 동일).
- 빌드 및 헬스 체크 통과.

## 2. 설계

### 2.1 UX 검토 (선택)

UI/레이아웃 요건이므로, §1.1에 따라 **UX** 서브에이전트로 계층 표시·스크롤 동작에 대한 검토를 요청할 수 있다. 기존 `20260225-sidebar-search-menu-hierarchy.md` §2.1 UX 권고(들여쓰기, 화살표, a11y)를 재사용·확장하여, "로그 검색"이 최상위 한 줄로 보이도록 하는 표시 방식과, 메뉴 영역 스크롤 시 시각적 피드백·접근성(a11y)을 반영할 수 있다.

### 기술 설계

#### 문제 분석

1. **계층 표시**: `AppSidebar.js`에서 MENU_TREE의 첫 노드 "로그 검색"(자식: "검색하기", "검색 이력")이 react-pro-sidebar의 SubMenu로 렌더링될 때, **부모 행이 최상위로 노출되지 않거나** 다른 최상위 메뉴(이력·승인, 통계, 관리)와 동일한 스타일/정렬로 보이지 않아, 자식만 들여쓰기된 고아처럼 보이는 상태.
2. **스크롤 회귀**: Sidebar/Menu 컨테이너에 **높이 제한 및 overflow 처리**가 없거나 변경되어, "이력·승인" 하위가 펼쳐지면 메뉴 목록 전체가 늘어나 상단 항목(로그 검색, 검색하기, 검색 이력)이 뷰포트 밖으로 밀려나고, 해당 영역에 스크롤이 없어 접근 불가.

#### 해결 방안

**1) 검색 메뉴 계층 표시 (문제 1)**

- **파일**: `frontend/src/components/AppSidebar.js`
- "로그 검색"을 **첫 번째 SubMenu**로 두고, **최상위 한 줄**로 렌더링되도록 보장한다. 이력·승인, 통계, 관리와 **동일한 레벨·정렬**로 보이게 한다.
- react-pro-sidebar가 첫 SubMenu를 다르게 렌더링하거나 숨기는 경우: **props 또는 스타일**을 조정하여 "로그 검색" 행이 다른 최상위 SubMenu와 동일한 형태(왼쪽 정렬, 화살표 등)로 보이게 한다.
- "검색하기", "검색 이력"은 "로그 검색"의 **자식**으로만 표시되며, "이력·승인" → "활동 이력", "승인 대기"와 같은 계층 스타일을 유지한다.

**2) 사이드바 메뉴 스크롤 복구 (문제 2)**

- **파일**: `frontend/src/components/AppSidebar.js`
- **Sidebar 또는 Menu 컨테이너**에 다음을 적용한다:
  - **높이 제한**: 예) `height: 100vh` 또는 `height: 100%`(부모 높이 기준)로 메뉴 목록 영역의 높이를 제한.
  - **세로 스크롤**: `overflowY: 'auto'`(또는 동일 효과의 CSS)를 적용하여, 메뉴 항목이 많거나 "이력·승인" 등이 펼쳐져도 **목록 영역 내부에서 스크롤**되도록 한다.
- 그 결과, "이력·승인"을 펼치고 하위를 선택해도 상단의 "로그 검색", "검색하기", "검색 이력"이 뷰포트 밖으로 사라지지 않고, **스크롤을 올려 접근 가능**하도록 한다.

### 변경 파일 목록

## 6. 원인 재분석 및 재조치 (미반영 시)

사용자 보고: "아무것도 바뀌지 않았는데" — 코드 변경·QA 통과에도 화면에서 개선이 보이지 않는 경우 아래를 적용한다.

### 6.1 가능한 원인

**스크롤(문제 2)**  
- react-pro-sidebar 구조: `Sidebar` → `StyledSidebarContainer`(height: 100%, overflow-y: auto) → 우리 **div**(flex: 1, minHeight: 0, overflowY: auto) → Menu.  
- **Container의 height: 100%**는 부모(StyledSidebar)에 명시적 높이가 있을 때만 유효. rootStyles로 `height: '100vh'`를 넘기지만, **비‑broken 모드**에서 Sidebar가 `position: relative`라 상위 레이아웃에 따라 높이가 정해지지 않을 수 있음.  
- 우리 div의 **flex: 1, minHeight: 0**은 **부모가 flex 컨테이너일 때만** 높이 제한을 받음. Container는 flex가 아니므로 div가 내용 높이만큼 늘어나 스크롤이 컨테이너에 걸리지 않을 수 있음.

**계층 표시(문제 1)**  
- **menuItemStyles.button**의 `level === 0`은 SubMenu의 **트리거(라벨) 행**에 적용되지만, 라이브러리가 첫 번째 SubMenu에 다른 기본 패딩/클래스를 줄 수 있음.  
- 라이브러리 클래스명: `ps-submenu-root`, `ps-menu-button`. 첫 번째 `.ps-submenu-root`만 다르게 렌더링되면 시각적 불일치가 남을 수 있음.

### 6.2 재조치 방안

**스크롤**  
- 메뉴를 감싼 래퍼에 **flex/퍼센트에 의존하지 않고** **명시적 높이**를 준다: `maxHeight: '100vh'`, `overflowY: 'auto'`.  
- 래퍼를 `height: '100vh'`로 고정해도 됨. 이렇게 하면 부모 체인과 무관하게 메뉴 영역만 세로 스크롤된다.

**계층 표시**  
- 첫 번째 SubMenu("로그 검색")에 **className**을 부여하고, 전역 또는 컴포넌트 내 스타일로 `.ps-menu-button`에 동일 패딩을 강제한다.  
- 또는 Sidebar에 **customStyles**/라이트웨이트 CSS 주입으로 `.ps-sidebar-container .ps-submenu-root:first-child .ps-menu-button { padding-left: 12px; }` 적용.

### 6.3 재조치 적용 내역 (2026-02-25)

- **AppSidebar.js**: 메뉴 래퍼 div를 `flex: 1, minHeight: 0, height: 100%` 대신 **`maxHeight: '100vh'`, `overflowY: 'auto'`, `overflowX: 'hidden'`** 로 변경. 첫 번째 SubMenu에 `className="sidebar-first-submenu"` 부여.
- **App.css**: `.sidebar-first-submenu.ps-submenu-root > .ps-menu-button { padding-left: 12px !important; }` 추가 (RTL 대응 포함).
- 빌드: `CI=false npm run build` → exit 0. 재검증(TC-01, TC-02) 및 필요 시 §5 갱신.
