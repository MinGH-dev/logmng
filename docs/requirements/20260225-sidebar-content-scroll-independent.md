# 20260225 - 사이드바·컨텐츠 스크롤 독립화

## 관련 요건
- **20260225-sidebar-topbar-layout-no-overlap.md**: 동일 주제(스크롤 분리)를 요구했으나, 구현 후에도 여전히 사이드바 스크롤과 메인 컨텐츠 스크롤이 동기화되어 동작하는 문제가 남아 있음. 본 요건은 **스크롤이 진짜로 독립**되도록 원인 수정을 명세한다.

---

## 1. 사용자 요건 내용

### 요건 설명
사이드바 메뉴 영역의 스크롤과 메인 컨텐츠 영역의 스크롤이 **여전히 동기화**되어 있다(한쪽을 스크롤하면 다른 쪽도 함께 움직임). 두 영역의 스크롤은 **서로 독립**이어야 한다.

- **사이드바만 스크롤**: 메인 컨텐츠 위치는 변하지 않아야 함.
- **메인 컨텐츠만 스크롤**: 사이드바 메뉴 위치는 변하지 않아야 함.

### 사용자 시나리오
1. 로그인 후 앱 메인 화면 진입.
2. 사이드바 메뉴가 많거나 메인 영역 콘텐츠가 길어 스크롤이 필요한 상태.
3. **문제**: 사이드바 메뉴를 스크롤하면 메인 컨텐츠도 함께 스크롤되거나, 메인 컨텐츠를 스크롤하면 사이드바 메뉴도 함께 스크롤됨(전체 페이지가 한 덩어리로 스크롤).
4. 사용자는 메뉴만 스크롤하거나 컨텐츠만 스크롤하고 싶음.

### 기대 결과
- **사이드바 메뉴만 스크롤**할 때 메인 컨텐츠의 스크롤 위치는 **유지**된다.
- **메인 컨텐츠만 스크롤**할 때 사이드바 메뉴의 스크롤 위치는 **유지**된다.
- 뷰포트(창) 자체는 스크롤되지 않고, **각 영역이 자체 스크롤 컨테이너**로만 스크롤된다.

## 2. 설계

### 기술 설계

#### 원인 분석
스크롤이 동기화되는 일반적인 원인은 **루트(또는 앱 최상위 컨테이너/body)가 스크롤 컨테이너**가 되어, 전체 페이지가 한 덩어리로 스크롤되기 때문이다. 이 경우 사이드바와 메인 영역 모두 그 안에 있어 함께 움직인다.  
이전 요건(`20260225-sidebar-topbar-layout-no-overlap.md`)에서 메인 컨텐츠 Box에 `overflowY: auto`, `minHeight: 0` 등을 적용했음에도 동기화가 남아 있다면, **루트(또는 앱 래퍼)에 높이 고정·overflow 제한이 없어** 여전히 창 전체가 스크롤되고 있을 가능성이 크다.

#### §2.1 Root cause re-analysis (재발 시)

**Observed behavior (관찰된 동작)**  
구현된 레이아웃(루트 `height: 100vh` + `overflow: hidden`, 메인 `minHeight: 0`, 사이드바 `overflow: hidden`) 적용 후에도 **사이드바 스크롤과 메인 컨텐츠 스크롤이 여전히 동기화**되어, 한쪽을 스크롤하면 다른 쪽도 함께 움직이는 상황이 지속됨.

**Possible remaining causes (잔존 원인 후보)**  
1. **html/body overflow**  
   - `html` 또는 `body`에 `overflow: hidden`이 적용되지 않아, 문서 루트가 여전히 스크롤 가능한 상태일 수 있음.  
   - React 앱 래퍼만 100vh·overflow hidden이어도, 상위 `html`/`body`가 스크롤되면 전체가 같이 스크롤됨.  
2. **Another ancestor scroll container**  
   - 사이드바와 메인 컨텐츠를 함께 감싸는 또 다른 조상 노드(예: `#root` 내부의 추가 wrapper, 레이아웃용 Box)가 `overflow: auto/scroll`이거나 높이가 내용에 따라 늘어나 스크롤 컨테이너가 되어 있을 수 있음.  
3. **react-pro-sidebar 내부 래퍼**  
   - `react-pro-sidebar` 라이브러리의 내부 wrapper가 **공통 스크롤 컨텍스트**를 만들거나, 메뉴 영역과 메인 영역이 같은 스크롤 부모 아래에 있게 되어 동기화가 발생할 수 있음.  
4. **Viewport/height 상속 문제**  
   - `100vh` 또는 `minHeight: 0`이 flex 체인 상에서 일부 노드에 누락되어, 실제 스크롤이 “두 개의 독립 컨테이너”가 아니라 상위 하나에서만 일어나고 있을 수 있음.

**Proposed next design options (다음 설계 옵션)**  
- **A. html/body overflow 명시**  
  - 전역 CSS(예: `index.css`, `App.css`) 또는 `index.html` 인라인에서 `html, body { height: 100%; overflow: hidden; }` 적용.  
  - 앱 래퍼(`#root` 또는 App 최상위 Box)에도 동일하게 `height: 100%`(또는 100vh), `overflow: hidden` 유지하여 **문서 레벨 스크롤이 발생하지 않도록** 함.  
- **B. 스크롤 루트를 명확히 두 개만 유지**  
  - **스크롤 루트 1**: 사이드바 **메뉴 wrapper**만 (고정 높이 + `overflow-y: auto`).  
  - **스크롤 루트 2**: 메인 컨텐츠 Box만 (flex: 1, minHeight: 0, `overflow-y: auto`).  
  - 그 외 모든 조상은 `overflow: hidden` 또는 `overflow: visible`(스크롤 불가)으로 하여, 스크롤이 위 두 영역 밖에서 발생하지 않도록 함.  
- **C. DOM 구조 점검**  
  - DevTools로 실제 DOM을 열어, 스크롤 시 `scrollTop`이 바뀌는 요소를 확인.  
  - 의도한 “사이드바 메뉴 wrapper”와 “메인 컨텐츠 Box”만 스크롤되는지, 그 상위(예: body, #root, pro-sidebar 내부 div)에서 스크롤이 일어나지 않는지 검증.  
  - 예상치 못한 스크롤 컨테이너가 있으면 해당 노드에 높이 제한·overflow 제거 또는 자식만 스크롤되도록 구조 변경.

#### 해결 방안

**1) 루트/앱 컨테이너**
- **뷰포트가 스크롤되지 않도록** 루트(또는 앱 최상위 컨테이너)에 다음을 적용한다.
  - **height: 100vh** (또는 100% 등으로 뷰포트 높이에 고정).
  - **overflow: hidden**.
- 그 결과, 창(페이지) 자체는 스크롤되지 않고, 내부 영역만 각각 스크롤된다.

**2) 사이드바 메뉴 영역**
- 메뉴 영역이 **고정 높이**를 가지며 **자체 스크롤**만 하도록 한다.
  - 높이 제한(예: 뷰포트 또는 부모 높이 기준).
  - **overflow-y: auto** (이미 시도된 바 있음; 동작 여부 확인 후 미흡 시 수정).
- 대상 파일: `frontend/src/components/AppSidebar.js` (필요 시).

**3) 메인 컨텐츠 영역**
- 메인 컨텐츠 Box가 **자체 스크롤 컨테이너**가 되도록 한다.
  - **높이 제한**: flex 레이아웃에서 **flex: 1**과 **minHeight: 0**을 체인에 적용하여, flex 자식이 남는 공간을 채우되 overflow 시 스크롤이 이 Box 안에서만 발생하도록 한다.
  - **overflow-y: auto**.
  - 메인 컨텐츠가 **다른 스크롤 가능 영역 안에 중첩**되어 있지 않도록 하여, 스크롤이 동기화되는 구조를 제거한다.
- 대상 파일: `frontend/src/App.js` (루트 구조 및 메인 컨텐츠 Box).

  - 메인 컨텐츠 영역 Box: **flex: 1**, **minHeight: 0** (flex 체인 상에서), **overflow-y: auto** 적용하여 메인 영역만 스크롤되도록 함.
