# 20260225 - 사이드바·상단바 레이아웃 중첩 제거 및 스크롤 분리

## 1. 사용자 요건 내용

### 요건 설명
1. **검색 상위 메뉴(로그 검색)가 상단 바에 가려지는 문제**: 레이아웃상 왼쪽 사이드바와 상단 바(상태정보 표시, AppBar)가 중첩되어, 상단 바가 사이드바 상단(로그 검색 등 상위 메뉴)을 덮어서 보이지 않는다.
2. **메뉴 스크롤과 컨텐츠 스크롤 분리**: 사이드바 메뉴 영역은 자체 스크롤, 메인 컨텐츠 영역은 자체 스크롤로 동작해야 하며 서로 독립적이어야 한다.
3. **레이아웃 중첩 제거**: 왼쪽 사이드바와 상단 상태정보 표시(AppBar)가 겹치지 않도록 레이아웃을 개선해야 한다.

### 사용자 시나리오
1. 로그인 후 앱 메인 화면 진입
2. 왼쪽 사이드바가 펼쳐진 상태에서 상단 메뉴(로그 검색 등)를 확인
3. **문제**: 상단 바(AppBar, position: fixed, full width)가 사이드바 위에 겹쳐 있어 로그 검색 등 상위 메뉴가 가려짐
4. 사이드바 메뉴가 많을 때 메뉴만 스크롤하고, 메인 영역은 별도로 스크롤하고 싶음

### 기대 결과
- 로그 검색 등 **상위 메뉴가 상단 바에 가려지지 않고** 전체가 보인다.
- **사이드바 메뉴 영역**만 스크롤 가능(overflow-y: auto 등).
- **메인 컨텐츠 영역**만 별도 스크롤 가능.
- 왼쪽 사이드바와 상단 바(AppBar)가 **레이아웃상 겹치지 않는다**.

## 2. 설계

### 2.1 UX 검토 (레이아웃 옵션 권장)
**UX 권장:**
- **옵션 (A) 권장 — AppBar를 메인 영역 위에만 배치.** 프로젝트 레이아웃 기준(상단 사용자 영역이 오른쪽 영역 상단)에 맞고, 사이드바를 화면 왼쪽 끝부터 세로로 끝까지 쓰면 네비게이션 영역이 명확하다. 사용자 인지 모델도 "왼쪽 네비·오른쪽 작업 영역(그 위에 사용자/로그아웃 바)"로 단순하다.
- **접근성:** (A)에서는 메뉴가 AppBar에 가려지지 않아, 키보드/스크린리더로 "사이드바 → 메인" 순서가 일정하고, "메인 콘텐츠로 건너뛰기"와의 조합도 자연스럽다. (B)도 랜드마크·포커스 순서만 잘 두면 무방하다.
- **일관성:** 왼쪽 고정 사이드바 + 오른쪽 작업 영역 + 상단 사용자 영역 구조에서, (A)는 "상단 사용자 영역 = 오른쪽 영역 상단"으로 해석되어 명세와 맞다.
- **설계 참고:** (A) 선택 시 AppBar의 `left`(또는 `marginLeft`)를 사이드바 폭(펼침/접힘)과 동기화하고, 사이드바 접힘 시 전환(transition)을 주어 깜빡임 없이 이동시키는 것이 좋다. AppBar는 메인 콘텐츠 위에만 올라가도록 `z-index`를 사이드바 Drawer보다 높게 두되, AppBar가 사이드바 위를 덮지 않도록 위치만 오프셋. 반응형에서는 뷰포트가 좁을 때 (B)처럼 "AppBar 전체 너비 + 그 아래 [사이드바|메인]" 폴백을 고려할 수 있다.

**요약:** UX·접근성·레이아웃 일관성 관점에서는 **옵션 (A)** 권장. 구현 단순화를 우선하면 (B)도 허용 가능.

### 기술 설계

#### 현재 레이아웃 (참고)
- **App.js**: Root Box (flex) → AppSidebar (full height) + main Box (flex:1) → AppBar (position: fixed, zIndex drawer+1) + content Box (mt: 7)
- AppBar가 **position: fixed**, **full viewport width**로 되어 있어 상단 전체를 덮고, 그 결과 사이드바 상단이 AppBar에 가려짐.

#### 문제 분석
1. AppBar가 뷰포트 전체 너비에 고정되어 사이드바 영역 위까지 덮음.
2. 사이드바와 메인 영역의 스크롤이 분리되어 있지 않거나, 한쪽 스크롤이 다른 쪽에 영향을 줄 수 있는 구조일 수 있음.

#### 해결 방안

**1. No overlap (중첩 제거)**  
다음 두 방식 중 **하나**를 선택하여 명세한다. (§2.1 UX 검토에서 **옵션 (A) 권장**.)

- **(A) AppBar를 메인 컨텐츠 영역 위에만 배치**  
  - AppBar에 `marginLeft`(또는 `left`) = 사이드바 폭(펼침 시)을 적용하여, AppBar가 **메인 컨텐츠 영역 위에만** 존재하도록 한다.  
  - 사이드바는 화면 왼쪽 끝부터 세로로 전부 노출되므로, 상단 바에 가려지지 않음.

- **(B) AppBar를 최상단 전체 너비로 두고, 그 아래에 사이드바 | 메인 영역 배치**  
  - AppBar는 full width로 유지하고, 그 **아래**에 한 행으로 [사이드바 | 메인 컨텐츠]를 배치한다.  
  - 사이드바와 메인 영역 모두 AppBar 아래에서 시작하므로 서로 겹치지 않음.

구현 시 (A)/(B) 중 하나를 선택하고, 선택 근거(또는 UX 권장)를 설계에 명시한다.

**2. Separate scroll (스크롤 분리)**  
- **사이드바 메뉴 영역**: 자체 스크롤 컨테이너(`overflow-y: auto` 등)로 높이 제한 후 메뉴만 스크롤.
- **메인 컨텐츠 영역**: 자체 스크롤 컨테이너로 메인 콘텐츠만 스크롤.  
두 영역의 스크롤은 서로 독립적으로 동작한다.

### 변경 파일 목록

#### 프론트엔드
- `frontend/src/App.js`
  - 루트 레이아웃 구조 조정: (A) 또는 (B)에 따라 AppBar 위치/영역, main·sidebar 배치 변경.
- `frontend/src/components/AppBar.js`
  - (A) 선택 시: position/offset(marginLeft 또는 left = sidebar width) 적용하여 메인 영역 위에만 표시.
  - (B) 선택 시: 필요 시 높이만 유지, 하위에 sidebar | content 행 배치하는 쪽은 App.js에서 처리.
- `frontend/src/components/AppSidebar.js`
  - 메뉴 영역에 고정 높이 + `overflow-y: auto`(또는 동일 효과) 적용하여 사이드바만 스크롤되도록 함.

### 테스트 시나리오

#### 시나리오 1: 상단 메뉴 가시성
1. 앱 접속 후 왼쪽 사이드바를 펼친 상태로 둠.
2. 사이드바 최상단(로그 검색 등) 메뉴가 상단 바에 의해 가려지는지 확인.
3. **검증**: 로그 검색 등 상위 메뉴 전체가 보여야 함.

#### 시나리오 2: 스크롤 독립성
1. 메뉴 항목이 많아 세로 스크롤이 필요한 상태에서 사이드바 메뉴만 스크롤.
2. 메인 영역 콘텐츠가 길 때 메인 영역만 스크롤.
3. **검증**: 메뉴 스크롤 시 메인 영역 위치 유지, 메인 스크롤 시 메뉴 위치 유지.

#### 시나리오 3: 빌드·헬스체크
1. `cd frontend && npm run build` 실행.
2. 서비스 재시작 후 `.cursor/commands/verify.md`에 따른 헬스체크 수행.
3. **검증**: 빌드 성공, 2xx 응답 및 정상 동작.
