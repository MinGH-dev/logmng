# 20260225 - 사이드바 검색 메뉴 계층 표시 개선

## 1. 사용자 요건 내용

### 요건 설명
사이드바에서 **"검색하기"**와 **"검색 이력"**이 "이력·승인", "통계", "관리"와 같은 **최상위 메뉴와 동일한 단계**로 보이거나, 부모인 **"로그 검색"**이 계층적으로 드러나지 않는 문제가 있다. 사용자 입장에서는 "검색하기"와 "검색 이력"이 **"로그 검색"의 하위 메뉴**임을 한눈에 알 수 있어야 한다.

### 사용자 시나리오
1. 로그인 후 앱 메인 화면 진입
2. 왼쪽 사이드바를 확인
3. **문제**: "검색하기", "검색 이력"이 "이력·승인", "통계", "관리"와 같은 들여쓰기/레벨로 나열되어 있고, 다른 상위 메뉴에 있는 오른쪽 화살표(>)가 없어 **"로그 검색"이 부모인지 시각적으로 구분되지 않음**
4. "이력·승인"을 펼치면 "활동 이력", "승인 대기"가 하위로 들여쓰기되어 부모–자식 관계가 명확한 반면, "로그 검색"은 부모로 보이지 않거나 자식이 동일 레벨로 보임

### 기대 결과
- **"로그 검색"**이 부모 메뉴로 명확히 보이고, 클릭 시 펼쳐지며 **"검색하기", "검색 이력"**이 그 하위(들여쓰기·시각적 종속)로 표시된다.
- "이력·승인" → "활동 이력", "승인 대기"와 **동일한 계층 스타일**(부모에만 화살표, 자식은 들여쓰기, 리프에는 화살표 없음)이 적용된다.
- 빌드 및 프론트엔드 헬스 체크 통과.

## 2. 설계

### 2.1 UX 권고 (Requirements 작성 시 UX 서브에이전트 피드백 반영)

**1. 들여쓰기(Indentation)**  
- 서브메뉴("검색하기", "검색 이력")는 부모("로그 검색")보다 **한 단계 안쪽**으로 보이도록 한다.  
- 권장: 부모 왼쪽 패딩/마진 대비 **24px ~ 32px 추가** 들여쓰기(프로젝트 기본 8px 그리드면 24px 또는 32px).  
- "이력·승인" → "활동 이력"/"승인 대기"와 **동일한 픽셀 값**을 사용해 전체 사이드바에서 2-depth가 일관되게 보이게 한다.

**2. 화살표 아이콘**  
- **부모만** 오른쪽 화살표(>) 표시: "로그 검색", "이력·승인", "통계", "관리" 등 확장 가능한 항목.  
- **리프 항목에는 화살표 없음**: "검색하기", "검색 이력", "활동 이력", "승인 대기" 등 실제 라우트로 이동하는 항목.  
- 화살표는 확장/축소 상태를 반영(예: 열림 = 아래 방향, 닫힘 = 오른쪽 방향)해도 되며, "이력·승인"에서 쓰는 방식과 동일하게 맞춘다.

**3. 시각적 일관성**  
- **로그 검색** 하위 두 항목은 **이력·승인** 하위 두 항목과 동일한 규칙 적용:  
  - 서브메뉴 폰트 크기/굵기: 부모와 동일하거나 한 단계 작게(예: 부모 medium, 서브 regular).  
  - 수직 간격: 부모–자식, 자식–자식 간격이 "이력·승인" 서브메뉴와 동일.  
  - 아이콘: 부모에만 아이콘을 두거나, 서브에도 둘 경우 "이력·승인" 서브와 같은 정렬/크기 규칙 사용.  
- 활성 경로 강조: 현재 페이지인 서브 항목("검색하기" 또는 "검색 이력")에만 배경/좌측 바/굵기 등으로 강조하고, `aria-current="page"` 사용(프로젝트 표준).

**4. 접근성(a11y)**  
- **부모 "로그 검색"**:  
  - `aria-expanded="true"|"false"`로 열림/닫힘 상태 노출.  
  - `aria-haspopup="true"` 또는 메뉴 역할에 맞는 `aria-haspopup` 사용.  
  - 키보드: Enter/Space로 확장·축소; 포커스 순서는 부모 → (확장 시) 첫 번째 자식 → 두 번째 자식 → 다음 부모.  
- **리프 "검색하기", "검색 이력"**:  
  - 링크/버튼 역할에 맞는 시맨틱 사용(예: `<a>` 또는 `role="menuitem"` 등).  
  - `aria-expanded` 없음(리프는 확장 불가).  
- 포커스 순서: 사이드바 내에서 위→아래, 부모 → 해당 자식들 순서 유지.  
- 스크린 리더: 부모 레이블("로그 검색")과 함께 "확장됨/축소됨" 안내 가능하도록 상태가 노출되면 좋음.

### 기술 설계

#### 문제 분석
- `frontend/src/components/AppSidebar.js`(react-pro-sidebar 사용): MENU_TREE에서 "로그 검색"이 부모이고 "검색하기", "검색 이력"이 자식으로 정의되어 있으나, **렌더링 시 부모가 최상위로 드러나지 않거나 자식이 동일 레벨로 표시**됨.
- "검색하기", "검색 이력"에 부모 전용 화살표(>)가 없어 리프로 인식되지만, 동시에 "이력·승인", "통계", "관리"와 같은 들여쓰기로 나열되어 **계층이 시각적으로 잘못 표현**됨.

#### 해결 방안
- **react-pro-sidebar**의 부모/자식 구조를 활용해 "로그 검색"을 **부모 메뉴(SubMenu 또는 확장 가능한 MenuItem)** 로 렌더링하고, "검색하기", "검색 이력"을 **그 자식**으로 렌더링.
- 부모 "로그 검색": 확장/축소 가능, **화살표만 부모에 표시** (§2.1 UX 권고).
- 자식 "검색하기", "검색 이력": **들여쓰기 및 스타일**을 "이력·승인" → "활동 이력", "승인 대기"와 동일하게 적용(§2.1 들여쓰기·시각적 일관성).
- 리프 항목에는 화살표 미표시; 접근성은 §2.1 a11y 권고에 따라 `aria-expanded`, 포커스 순서 등 반영.

### 테스트 시나리오

#### 시나리오 1: 사이드바 계층 표시
1. 앱 접속 후 사이드바가 펼쳐진 상태에서 "로그 검색" 항목 확인.
2. "로그 검색" 클릭하여 하위 메뉴 펼침.
3. "검색하기", "검색 이력"이 "로그 검색"보다 들여쓰기되어 하위로 보이는지, 그리고 "이력·승인" 하위와 같은 스타일인지 검증.

#### 시나리오 2: 시각적 일관성
1. "이력·승인" → "활동 이력", "승인 대기"의 들여쓰기·화살표 규칙 확인.
2. "로그 검색" → "검색하기", "검색 이력"에 동일 규칙이 적용되었는지 비교 검증.

#### 시나리오 3: 빌드 및 헬스 체크
1. `cd frontend && CI=false npm run build` 실행.
2. `./scripts/dev-services.sh frontend restart` 후 `curl`로 localhost:3001 2xx 확인.
