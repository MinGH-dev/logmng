# 20260224 - Image log 검색 시 암호화 구간만 encrypted 하이라이트

## 1. 사용자 요건 내용

### 요건 설명
Image log 검색 시 "성공" 등 키워드로 검색하면, 암호화된 값은 정상적으로 encrypted 스타일로 하이라이트되는데, **대괄호로 감싸진 일반 JSON 값**(예: 배열·객체 문자열)까지 encrypted로 하이라이트되는 문제가 있음. 암호화 구간만 encrypted 하이라이트되도록 식별 기준을 명확히 해야 함.

### 사용자 시나리오
1. 사용자가 Image log에서 "성공" 등 키워드로 검색한다.
2. 결과에서 키워드 하이라이트와 암호화된 값(주황색) 하이라이트가 표시된다.
3. **문제**: 쌍따옴표 밖의 대괄호(예: JSON 배열 `[1,2,3]`) 또는 쌍따옴표 안이지만 “대괄호로 시작 + 그 다음에 쌍따옴표가 오지 않는” 일반 문자열 값도 encrypted로 하이라이트됨.
4. **기대**: encrypted 하이라이트는 “쌍따옴표 안에 있고, 대괄호로 시작한 뒤 **대괄호 직후에 쌍따옴표가 오는**” 구간에만 적용된다.

### 기대 결과
- 암호화 여부 식별 기준: **쌍따옴표 안에 있고**, 값이 **대괄호로 시작**하며, **대괄호 직후에 쌍따옴표가 오는** 경우에만 encrypted로 간주하여 하이라이트한다.
- 그 외 대괄호로 감싸진 JSON 값(배열, 또는 `"[...]"` 형태가 아닌 일반 문자열)은 encrypted 하이라이트 대상에서 제외한다.

## 2. 설계

### 기술 설계

#### 문제 분석
1. 현재 `ImageLogTable.js`의 `highlightKeywordsAsHtml`에서 암호화 패턴이 `/\[([^\]]+)\]/g`로 되어 있어, **모든** `[ ... ]` 구간을 암호화된 값으로 간주함.
2. JSON 내 배열 값(예: `[1,2,3]`)이나, 쌍따옴표 안이지만 `["...]` 형태가 아닌 값까지 encrypted로 하이라이트됨.

#### 해결 방안
- **암호화 구간 식별 규칙**: 다음을 모두 만족할 때만 암호화된 값으로 판단한다.
  1. **쌍따옴표 안**에 있는 문자열 값이다 (즉, `"` 바로 다음에 `[`가 옴).
  2. 값이 **대괄호로 시작**한다.
  3. **대괄호 직후에 쌍따옴표**가 온다 (즉, `["` 또는 `[\"` 형태).
- 정규식으로는 “쌍따옴표로 시작하는 문자열 값 중, 내용이 `[`로 시작하고 그 다음에 `"`가 오는 경우”에 해당하는 `[...]` 블록만 매칭하도록 변경한다.
- 구현 시: `encryptedPattern`을 위 규칙에 맞게 수정하고, 기존처럼 `encryptedMatches`를 채운 뒤 하이라이트·마스킹 로직은 그대로 사용한다.

#### 암호화 패턴 (규격)
- **매칭 대상**: JSON 문자열 값으로서, 값이 `[`로 시작하고 그 직후에 `"`(또는 이스케이프된 `\"`)가 오는 구간.  
  예: `"[\"base64...\"]"` 또는 `"[\"..."\]"` 형태.
- **제외**: `"key": [1,2,3]`, `"key": "일반문자열"`, `"key": "[문자열인데 따옴표가 대괄호 직후에 없음"` 등은 encrypted로 처리하지 않음.

### 변경 파일 목록

#### 프론트엔드
- `frontend/src/components/ImageLogTable.js`
  - `highlightKeywordsAsHtml` 내 `encryptedPattern` 수정: 쌍따옴표 안 + 대괄호로 시작 + 대괄호 직후 쌍따옴표가 오는 경우에만 매칭하도록 변경.
  - `encryptedMatches` 수집 로직은 기존과 동일하게 “전체 `[ ... ]` 블록”을 사용하되, 위 패턴에 맞는 구간만 수집.
