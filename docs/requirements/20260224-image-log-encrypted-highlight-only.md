# 20260224 - Image log 검색 시 암호화 구간만 encrypted 하이라이트

## 1. 사용자 요건 내용

### 요건 설명
Image log 검색 시 키워드로 검색했을 때, **암호화 데이터**(`"[암호화데이터]"` 형태)에만 encrypted(주황) 하이라이트를 적용하고, **일반 데이터**(JSON 배열 등 `[일반데이터]`)에는 encrypted 하이라이트를 적용하지 않아야 함. 구분 기준은 "쌍따옴표 안에 있는 `[xxx]`" 여부만 해당.

### 사용자 시나리오
1. 사용자가 Image log에서 키워드로 검색한다.
2. 결과에서 키워드 하이라이트와 암호화된 값(주황색) 하이라이트가 표시된다.
3. **기대**: `"[암호화데이터]"`(JSON 문자열 값)인 구간만 encrypted로 하이라이트되고, `[일반데이터]`(예: JSON 배열 `[1,2,3]`)는 encrypted 하이라이트가 적용되지 않는다.

### 기대 결과
- **암호화 식별 기준**: 쌍따옴표 **안**에 있는 `[xxx]`(JSON 문자열 값이 `[ ... ]` 형태인 경우)만 encrypted로 간주하여 하이라이트한다.
- **제외**: 쌍따옴표 **밖**에 있는 `[xxx]`(JSON 배열 등)는 encrypted 하이라이트 대상에서 제외한다.

## 2. 설계

### 기술 설계

#### 문제 분석
1. 초기: `/\[([^\]]+)\]/g`로 **모든** `[ ... ]`를 암호화로 간주해 배열 `[1,2,3]`까지 하이라이트됨.
2. 이전 수정에서 "대괄호 직후 쌍따옴표" 조건을 넣었더니, 실제 암호화 값 `"[암호화데이터]"`가 하이라이트되지 않는 문제 발생.

#### 해결 방안
- **암호화 구간 식별 규칙**: **쌍따옴표 안에 있는 `[xxx]`**만 암호화로 판단한다. 즉, JSON 상에서 문자열 값이 `"[...]"` 형태인 경우만 해당.
- 정규식: `/"(\[[^\]]*\])"/g`로 쌍따옴표로 감싸진 `[...]` 블록만 추출. 별도 "대괄호 직후 따옴표" 필터는 사용하지 않음.
- **제외**: `"key": [1,2,3]`처럼 쌍따옴표 밖에 있는 `[ ... ]`(배열)는 위 패턴에 매칭되지 않으므로 encrypted 하이라이트 대상 아님.

#### 암호화 패턴 (규격)
- **매칭 대상**: JSON 문자열 값 `"[xxx]"` 전체에서 괄호 부분만, 즉 `[xxx]`(쌍따옴표 직후에 `[`로 시작해 `]`로 끝나는 구간).
- **제외**: `"key": [1,2,3]`, `"key": "일반문자열"` 등 쌍따옴표 밖의 `[ ... ]` 또는 `[`로 시작하지 않는 문자열.
