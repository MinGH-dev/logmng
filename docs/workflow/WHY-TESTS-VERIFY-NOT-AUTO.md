# 테스트·검증이 "자동"으로 안 된 이유

## 기대하신 동작

1. 테스트 계획 수립 → 테스트 케이스 작성 → 단위/통합 테스트 수행  
2. 문제 시 하위 요구사항(bugfix) 생성 → 오류 없을 때까지 반복  
3. **모듈 수정 시** 자동으로 테스트 실행 및 정상 실행 여부 검증  

## 왜 안 됐는지 (원인)

### 1. "자동" 실행 트리거가 없음

- `.cursor/commands/verify.md`, `run-tests.md`는 **에이전트(또는 사용자)가 실행하는 절차서**입니다.
- **파일 저장 시**, **커밋 시**, **모듈 수정 시**에 Cursor가 스스로 테스트를 돌리거나 `/verify`를 실행하는 기능은 **없습니다**.
- 즉, "모듈 수정 시 자동 실행"은 **문서에 적힌 절차**일 뿐, 실제로 자동으로 돌아가는 CI/훅이 프로젝트에 설정돼 있지 않습니다.

### 2. 에이전트가 절차를 끝까지 수행하지 않음

- 코드 수정까지 한 뒤, **단위 테스트 실행**(`mvn test` / `npm test`) → **§5 테스트 결과 기록** → **/verify**(재시작·헬스 확인) → **실패 시 bugfix 하위 요건 생성** 순서가 **강제되지 않았습니다**.
- 규칙에는 "개발 후: 단위/통합 테스트 수행 → §5 기록 … 검증 시 재시작·확인은 자동"이라고 되어 있지만,  
  **에이전트가 코드 수정 후 반드시 그 단계를 수행하도록** 명시된 규칙이 없어서, 구현만 하고 테스트/검증 단계를 건너뛸 수 있었습니다.

### 3. 실제 자동화(CI/훅) 미설정

- 프로젝트 루트(dev)에는 **pre-commit**, **husky**, **GitHub Actions** 등 **코드 변경 시 테스트를 돌리는 자동화**가 없습니다.
- 따라서 "모듈 수정 시 자동 실행"은 **설정만으로는 동작하지 않습니다**.

## 어떻게 하면 되게 할 수 있는지

### A. 에이전트가 절차를 빠짐없이 수행하도록 (권장)

- **코드 수정을 끝낸 뒤**, 에이전트가 **반드시** 다음을 수행하도록 규칙을 추가했습니다.
  - `backend/` 또는 `frontend/` 수정 시: **단위 테스트 실행** → 결과를 요건 문서 **§5**에 기록.
  - 그 다음 **검증(재시작·헬스 확인)** 수행. 실패 시 **bugfix 하위 요건** 생성 후 재시도.
- 이렇게 하면 "사람이 /verify, /run-tests를 치지 않아도" **에이전트가 작업 마무리 시** 테스트·검증을 수행하게 됩니다.
- 적용 규칙: `.cursor/rules/post-change-test-verify.mdc` 참고.

### B. 실제 자동화 추가 (선택)

- **pre-commit 훅**: 커밋 전 `mvn test` / `npm test` 실행 (실패 시 커밋 차단).
- **GitHub Actions(또는 CI)**: push/PR 시 테스트·검증 스크립트 실행.
- 이렇게 하면 "모듈 수정(커밋/푸시)" 시 **Cursor와 무관하게** 테스트가 자동 실행됩니다.

### C. 사용자가 명시적으로 실행

- 작업 마무리 시 **직접** `/run-tests` → `/verify` 실행.
- 또는 에이전트에게 "이번 수정에 대해 run-tests하고 verify까지 해줘"라고 요청.

---

**요약**:  
"자동"이라고 적힌 것은 **에이전트가 사용자에게 재시작을 요청하지 않고 직접 재시작·확인을 한다**는 의미였고, **파일이 바뀔 때마다 시스템이 스스로 테스트를 돌리거나** 하는 구조는 없었습니다.  
그래서 **에이전트가 코드 수정 후 반드시 테스트·검증을 수행하는 규칙**을 추가했고, 필요하면 pre-commit/CI까지 두면 "모듈 수정 시 자동 실행"에 더 가깝게 맞출 수 있습니다.
