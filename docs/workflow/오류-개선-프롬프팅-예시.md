# 오류 개선 요청 시 프롬프팅 예시

오류/버그를 개선할 때 Cursor에 **어떻게 요청하면** 프로젝트 워크플로우(요건 문서 → §3 테스트 계획 → 수정 → 테스트·검증)를 따르게 할 수 있는지 예시를 정리했다.

---

## 1. 기본 패턴 (오류 메시지 + 개선 요청)

아래처럼 **오류 내용**과 **"개선해줘"** 를 함께 주면, 규칙(error-first-workflow)에 따라 요건 문서·§3을 먼저 만들고 그 다음 수정한다.

**예시 1 — 오류만 붙여넣고 요청**
```
아래 오류 나와. 개선해줘.

[여기에 에러 로그/스택 트레이스 붙여넣기]
```

**예시 2 — 재현 방법까지 적어 주기**
```
활동 통계 API 호출 시 500 에러 나와. 로그인한 상태에서 통계 화면 들어가면 발생해.
개선해줘.

[에러 로그 또는 응답 본문 붙여넣기]
```

**예시 3 — 오류 + 예상 원인 힌트**
```
이미지 로그 검색 시 datastring 검색이 안 돼. 백엔드 쿼리 조건이 빠진 것 같아.
이 오류 개선해줘.

[관련 로그/요청·응답 붙여넣기]
```

---

## 2. 워크플로우를 명시해서 요청 (추천)

**"요건 문서와 §3 테스트 계획 먼저, 그 다음 수정"** 을 분명히 하고 싶을 때는 아래처럼 쓴다.

**예시 4 — 워크플로우 순서 강조**
```
아래 오류 개선해줘. **요건 문서 작성하고 §3 테스트 계획 세운 다음에** 수정 진행해줘.
todo도 워크플로우 순서대로 만들어줘.

[오류 메시지/로그 붙여넣기]
```

**예시 5 — fix 워크플로우 언급**
```
이 에러 수정해줘. 오류 수정 워크플로우(fix) 따라서: 요건 문서 → §3 테스트 방안 → 수정 → 테스트·검증 → §6 오류 조치 결과 기록까지 해줘.

[오류 내용 붙여넣기]
```

**예시 6 — 커맨드와 함께**
```
/follow-workflow 적용해서 아래 오류 개선해줘. 체크리스트 순서대로 todo 만들고 진행해줘.

[오류 메시지 붙여넣기]
```

---

## 3. 코드만 바로 수정하고 싶을 때 (예외)

이미 요건 문서와 §3이 있거나, **코드만 최소 수정**하고 싶을 때는 워크플로우를 우회하라고 명시한다.

**예시 7**
```
이 오류는 **코드만 최소한으로 수정**해줘. 요건 문서·테스트 계획 생략해도 돼.
[오류 붙여넣기]
```

---

## 4. 요약

| 목적 | 프롬프트 핵심 문구 |
|------|-------------------|
| 오류 개선 (워크플로우 따름) | "아래 오류 개선해줘" + 오류 내용 붙여넣기 |
| 순서·todo까지 강제 | "요건 문서·§3 먼저, todo는 워크플로우 순서대로 만들어줘" 또는 "/follow-workflow 적용해서" |
| 오류 수정 전 과정 명시 | "오류 수정 워크플로우(fix) 따라서 요건 문서 → §3 → 수정 → 테스트·검증 → §6까지" |
| 코드만 수정 (예외) | "코드만 최소 수정해줘. 요건 문서·테스트 계획 생략해도 돼" |
