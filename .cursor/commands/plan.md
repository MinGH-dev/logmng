# Plan before code

Complete the following **before** starting development (code changes).

## Order

1. **Gather and analyze requirements** — Summarize user request, error message, or feature need.
2. **Write requirement doc** — `docs/requirements/yyyyMMdd-name.md` with §1 user requirement, §2 design. Template: `docs/template/REQUIREMENT_TEMPLATE.md`.
3. **§3 Test plan** — Write the test case list in the requirement doc §3.
4. (If complex) Update spec/branch, then proceed to development.

## References

- **Checklist**: `docs/workflow/WORKFLOW_CHECKLIST.md`
- **Detail and examples**: `docs/workflow/DEVELOPMENT_WORKFLOW.md`
- **Errors too**: Do not go straight to code from an error; do requirement doc + §3 first. (`error-first-workflow.mdc`)

Use this command when you want to apply the above order: fill the requirement doc and §3, then develop.
